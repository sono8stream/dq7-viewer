# 表情差分(瞬き・口パク)テクスチャの格納形式

`CHARACTER/pXXXX_jNN.bcmdl.lz`に埋め込まれている`_kao`(素顔ベース)/`_e0`(目)/`_m0`
(口)のテクスチャは、いずれも静止画1枚のみで差分バリエーションを持たない。

瞬きや会話中の口パクに使われる差分画像は、別ファイル
**`TEXTURE/pXXXX_jNN_face.bctex.lz`**に格納されている。

## ファイルの中身

`pXXXX_jNN_face.bctex.lz`はキャラ×職業の組み合わせごとに存在し（仲間キャラ）、
NPCモデルは`TEXTURE/pXXXX_face.bctex.lz`（職業部分なし）。1ファイルにつき次のような
テクスチャを持つ:

```
pXXXX_jNN_m0 ... pXXXX_jNN_m7   (口パーツ、最大8枚。欠番がある場合あり)
pXXXX_jNN_e0 ... pXXXX_jNN_e8   (目パーツ、最大9枚。欠番がある場合あり)
```

インデックス0(`m0`/`e0`)は`.bcmdl.lz`本体に埋め込まれているデフォルト表情と同一画像。

**訂正:** テクスチャは常にRGBA5551・32x32ではない。全307ファイルの集計:
32x32 RGBA5551（2179枚）、64x32 RGBA5551（168）、32x32 ETC1A4（157）、
16x16 ETC1A4（34）、64x32 RGBA4（24）、16x16 RGBA5551（17）、ほかに少数の
32x32・64x64 RGBA4、64x64 ETC1A4 / RGBA5551。

よくあるスロットの組: e0〜e2＋m0〜m2・m6（123ファイル）、e0〜e2のみ（63）、
e0〜e3・e6〜e8＋m0〜m7（44）。名前の接頭辞はファイル名と一致しないことがある
（キーファのj00の20個のコピーは`p0003_j00_*`のまま、いくつかのNPCは`p102_*`の
ような別の接頭辞）。下記の通り、ゲームは接頭辞を見ないので問題にならない。

## ゲームでの差し替え方

ExeFSのコードから（ベースROMの仮想アドレス）:

- `CharacterObject::setupFaceAnimation`（`0x1177c8`）が
  `"TEXTURE/p%04d_j%02d_face.bctex.lz"`（パーティのスロット7未満）または
  `"TEXTURE/p%04d_face.bctex.lz"`でパスを作って読み込み、モデルの**`FaceMaterial`**
  という名前のマテリアルを探す。
- 顔ファイルの各テクスチャを、**名前の末尾2文字**でスロットに登録する:
  `e`＋数字 → 目のスロット<数字>、`m`＋数字 → 口のスロット<数字>。接頭辞は比較しない
  （だから`p0003_j00_*`のままのキーファのコピーも動く）。後のテクスチャが同じスロットを
  上書きし、空きスロットはスロット0になる。
- `CharacterObject::execute`（`0x119458`/`0x1194a4`の呼び出し）が
  `CharacterObject::changeTexture(this, 顔テクスチャ番号, mapper, ...)`（`0x115f70`）を
  呼び、FaceMaterialのテクスチャマッパー`mapper`のテクスチャを差し替える。目は
  `[this+0x7d0]`（=1）、口は`[this+0x7d4]`（=2、目の無いキャラは1）のマッパーで、
  どちらもキャラのレコードのフラグ（`+0x50`のbit1、`+0x51`）から決まる。
- このレコードは`LEVELDATA/dq7_chara_list.dat`のモデルの行（20バイトのヘッダの後に84バイトの行。
  `+0x48` u16 モデル番号、`+0x4A` `pNNNN`）:

  | 欄 | 値 | 意味 |
  | --- | --- | --- |
  | `+0x50` bit1 | 立っている | 目のアニメ（マッパー1） |
  | `+0x51 & 3` | 0 | 口のアニメなし（927行中712行） |
  | `+0x51 & 3` | 1 | 口テクスチャ（173行） |
  | `+0x51 & 3` | 2 | 口テクスチャなし。代わりに`CharacterObject`がvtable`+0x13C`を8で呼ぶ。`LipSyncRemoteControl::jawExec` / `jawStart`があごの骨側の処理（42行。p0184・p0158など） |

  行の無いモデル番号は表情が動かない（`setupFaceAnimation`がすぐ戻る）。
- 顔ファイルを持つ全307モデルで、FaceMaterialの目のステージには`<x>_e0`、口のステージには
  `<x>_m0`という名前のテクスチャが入っている: 目1＋口2（234モデル）、目1のみ（72）、
  口1のみ（1）。
- TXOBの大きさの欄: `+0x18`が高さ、`+0x1C`が幅（口の画像は幅64・高さ32で、逆ではない）。
- 口の段が無いFaceMaterialと有るものの違いは次だけ: `+0x168` 使うTextureCoordの数（2→3）、
  TextureCoords[2]（`+0x16C + 2*0x58`）、TextureMappers[2]（`+0x27C`のポインタ）、`+0x2A8` /
  `+0x2AC` / `+0x2C8`のハッシュ、TexEnvのステージ1（`033f055f / 300 / 4`: Interpolate(Previous,
  Texture2, Texture2のα)）と、それ以降の段が1つ後ろへずれること。TexEnvの1段は0x1Cバイトで、
  ソース・ヘッダ・オペランド・コンバイナ・色・スケールと、段に属さない1語。
- 口のUVは正面からの平面投影。`u`は`|x|`に比例（中心線でu=0、画像は口の半分でミラーされる）、
  `v`は`y`に比例。半分の向きが逆のモデルもあり、少数（p0014）は口全体の1枚で`u`が`x`に比例する。

スロットの見た目（例: NPCのp0122）: `e1`目を閉じる、`e2`細目、`m1`/`m2`/`m6`
大きさの違う開いた口。

## ビュアー

モデルページで、顔ファイルがあるモデルは3Dツールバーに**目**/**口**の選択欄が出る。
スロットを選ぶと、FaceMaterialの目・口のステージ（ゲームと同じステージ。ビュアーには
キャラのレコードが無いので、モデル内の`<x>_e0`/`<x>_m0`というテクスチャ名から決める）の
テクスチャが差し替わる。情報パネルには全スロットをサムネイルで表示する。
API: `/api/model`が`face: {file, eyes: [{slot, name}], mouths: [...]}`と、FaceMaterialの
シェイプに`faceStages: {eye, mouth}`を返す。
`/api/model/face_texture?file=<モデル>&name=<テクスチャ>`で差分1枚を返す。

## フォーマット

`.bctex.lz`はCGFX(BCRES)のTexturesのみを持つ形式で、LZ11圧縮。CGFXの共通構造
([`bcmdl_format.md`](bcmdl_format.ja.md)参照)のTXOBチャンクと同じデコード手順で
読める。
