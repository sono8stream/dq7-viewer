# マップモデルパック（`MAP/MAPDATA/*.pack.lz`）仕様

フィールド・町・ダンジョンのマップは、マップコードごとに1つのLZ11圧縮
「マップパック」として格納されている（`MAP/MAPDATA/<マップコード>.pack.lz`の
2222ファイル＋`MAP/z01n2f7.pack.lz`）。1つのパックに、そのマップの全3D部品・部品の配置・
コリジョンメッシュ・いくつかのシーンパラメータ・共有テクスチャが入っている。
本ドキュメントは実ファイルで確認できた構造のみを記載する（未確認の点はその旨を
明記）。Webアプリの`mappack.py`がこのレイアウトを実装し、「マップ3D」ページで
描画する。

## 汎用チャンクコンテナ

パック内のすべてのチャンクは同じコンテナヘッダを持つ（すべてリトルエンディアン）:

| オフセット | 型 | 内容 |
| --- | --- | --- |
| `+0x00` | char[16] | タグ（NUL埋め。`MODEL`, `FldData`, `FILE`, `COLL`, `PARM`, `WNOD`） |
| `+0x10` | u32 | エントリ数 |
| `+0x14` | u32 | データ基準: エントリのオフセットは「コンテナ先頭＋この値」からの相対 |
| `+0x18` | u32 | テーブル領域のサイズ = データ基準 − `0x20` |
| `+0x20` | `{u32 offset, u32 size}[エントリ数]` | エントリテーブル |

サイズ0のエントリは空。最上位コンテナでは、最後のエントリの末尾が
（展開後の）ファイル末尾と一致する。

## 最上位（`MODEL`、6エントリ）

| # | タグ | 内容 |
| --- | --- | --- |
| 0 | `WNOD` | 配置ノード（1エントリ＝1つの`GNOD`レコード） |
| 1 | `MODEL` | 入れ子のコンテナ: 部品ごとに1つの`FldData` |
| 2 | `FILE` | 部品名テーブル（`NRML` / `CMMN` / `LODM`） |
| 3 | `COLL` | コリジョン（セクションのコンテナ、後述） |
| 4 | `PARM` | シーンパラメータ（`BACK` / `CAMR` / `FOG `） |
| 5 | `CGFX` | `Textures`辞書だけを持つCGFX。全部品で共有 |

コリジョンを持たないパック（`a_*.pack.lz`のような単体のアニメ付きオブジェクト等）
ではエントリ3が空（サイズ0）。

## `FldData`（部品1つ）

3エントリのコンテナ:

| # | 内容 |
| --- | --- |
| 0 | `Models`辞書にモデルを1つ持つCGFX（モデル名＝部品名） |
| 1 | `Models`＋`SkeletalAnims`を持つCGFX（ごく小さいプレースホルダの場合あり） |
| 2 | `MaterialAnims`を持つCGFX（水面のスクロール等）、または空 |

### テクスチャ参照

部品のCGFXは通常、自前の`Textures`辞書を持たない（唯一の例外は
`MAP/z01n2f7.pack.lz`で、部品が自身のテクスチャ1枚を持つ）。各マテリアルの
テクスチャマッパーは
インラインの`GfxTextureReference`オブジェクト（型ワード`0x20000004`の`TXOB`）を
指しており、0x18バイトの`GfxObject`ヘッダの直後`+0x18`が`Path`文字列への
自己相対ポインタになっている。この`Path`が、パックの共有`CGFX`（最上位エントリ5）
内（上記の例外では部品自身の辞書内）のテクスチャ名である。全2223パック
（78970シェイプ）で、すべての参照が自パック内で解決する。

### 頂点フォーマットとマテリアルのコンバイナ

部品のシェイプは`position`・`color`・`uv0`（float32）を持ち、法線は持たない。
陰影は頂点カラー（RGBA、0〜1）に焼き込まれている。サンプルしたマップの
全マテリアル（大きなマップ2つで648マテリアル）が、TexEnvのステージ0 =
`Modulate(PrimaryColor, Texture0)`、残りのステージ = `Replace(Previous)`、
つまり「テクセル × 頂点カラー」になっている。アルファテストとカリングは
通常のCGFXモデルと同様にマテリアルごとに持つ。

## `WNOD` / `GNOD`（配置）

`WNOD`はコンテナで、各エントリが`GNOD`レコード1つ。`+0x08`のワードは
バージョンで、名前欄の長さを決める:

| バージョン（`+0x08`） | 名前欄の長さ | レコードサイズ | 出現箇所 |
| --- | --- | --- | --- |
| `0x00010500` | 32 | 0xB0 | `MAP/MAPDATA/*.pack.lz`の全71213ノード |
| `0x00010400` | 16 | 0xA0 | `MAP/z01n2f7.pack.lz`のみ（2ノード） |

バージョン`0x00010500`のレイアウト（`0x00010400`では名前以降の全フィールドが
0x10手前にずれる）:

| オフセット | 型 | 内容 |
| --- | --- | --- |
| `+0x00` | char[4] | `GNOD` |
| `+0x04` | u32 | ノード種別: `0` = ルート, `1` = 部品インスタンス |
| `+0x08` | u32 | バージョン（上表） |
| `+0x0C` | i32 | 部品インデックス（入れ子`MODEL`内の`FldData`番号）。ルートは`-1` |
| `+0x10` | char[32] | 名前（部品のモデル名・`NRML`名と一致） |
| `+0x30` | vec4 | 平行移動（w = 1） |
| `+0x40` | vec4 | 回転（ラジアン、x, y, z。観測されたのはy回転のみ） |
| `+0x50` | vec4 | スケール |
| `+0x60` | vec4 | バウンディングボックス最小（部品ローカル） |
| `+0x70` | vec4 | バウンディングボックス最大（部品ローカル） |
| `+0x80` | 0x30バイト | 種別・部品ごとのパラメータ（未解読） |

部品のジオメトリは部品ローカル座標で格納されている: スキニングの無い部品では、
ノードのバウンディングボックスが部品の頂点範囲と完全に一致する。ワールド配置は
`平行移動 · 回転 · スケール · 頂点`。y回転しか現れないため、オイラー角の
合成順序は未確認。ノードは階層を持たず（すべてルート直下）、親を示す
フィールドは見つかっていない。

ルートノードのバウンディングボックスは、遠景部品も含むマップ全体を覆う。

## `FILE`（部品名テーブル）

3セクションのコンテナ。各セクションは4文字のタグで始まり、`+0x08`にu32の
レコード数を持つ:

- `NRML`: `+0x10`から0x30バイトのレコード、名前は`+0x00`。`NRML[i]`が
  `FldData`の*i*番。GNODノードはこれらの部品だけを参照する（部品インデックス
  < NRMLのレコード数）。
- `CMMN`: アニメ付きの共通オブジェクト（ドア等、`a_wdoor02_1`のような名前）。
  その`FldData`はNRML部品の後ろに並ぶ。`WNOD`からは配置されない。
  レコードのレイアウトは未解読。
- `LODM`: 存在するが、確認したファイルでは空。

## `COLL`（コリジョン）

セクションのコンテナ。全2223パック中1795パックに存在する。どの`COLL`も
`PLGN`・`GRDS`・`NULL`を持ち、大半は`TINF`・`ROOT`・`CELL`も持つ。`AREA`と
`PATD`はそれぞれ1パックのみ。解読済みは`PLGN`のみ:

| オフセット | 型 | 内容 |
| --- | --- | --- |
| `+0x00` | char[4] | `PLGN` |
| `+0x04` | u32 | `0x40` |
| `+0x10` | u32 | ポリゴン数 *n* |
| `+0x20` | レコード[*n*] | 各0x80バイト |

ポリゴンレコード:

| オフセット | 型 | 内容 |
| --- | --- | --- |
| `+0x00` | u32 | `1` = 四角形, `0` = 三角形（4番目の頂点はゼロ埋め） |
| `+0x04` | u32[3] | 属性（未解読） |
| `+0x10` | vec4[4] | 頂点（外周順、w = 0） |
| `+0x50` | vec4 | 面法線 |
| `+0x60` | vec4 | バウンディングボックス最小（w = 1） |
| `+0x70` | vec4 | バウンディングボックス最大（w = 1） |

確認した全レコード（無作為に選んだ60パック、9970レコード）で、バウンディング
ボックスは3つまたは4つの頂点のmin/maxと一致する。コリジョンはワールド座標
（ノード変換なし）。

## `PARM`（シーンパラメータ）

3セクションのコンテナ。各セクションは16バイトのタグとそれに続くデータ:

| タグ | データ |
| --- | --- |
| `BACK` | vec4 RGBAのクリアカラー（0〜1） |
| `CAMR` | float×4（意味は未解読） |
| `FOG ` | 未解読（確認したファイルでは全てゼロ） |

## 未解決事項

- `GNOD`の`+0x80`以降のパラメータの意味、`CMMN`のレコードレイアウトと、
  CMMNオブジェクトがどう配置されるか。
- `PLGN`以外の`COLL`セクションと、`PLGN`の属性ワード。
- `PARM`の`CAMR`・`FOG `のフィールド。
- バインドポーズの頂点がノードのバウンディングボックスを超える、スキニング
  された部品（ボーンアニメ付きオブジェクト）。
