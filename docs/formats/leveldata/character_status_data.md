# キャラクターステータス関連データファイル仕様

対象: RomFS内 `LEVELDATA/` 配下の、プレイアブルキャラ・ゲスト・NPCのステータスに
関わるバイナリテーブル群。

## ファイル一覧

| ファイル | サイズ | ヘッダ | レコード数/サイズ | 内容 |
|---|---|---|---|---|
| `dq7_player_level1.dat` 〜 `_level6.dat` | 各4020byte | nrec=100, rsize=40 | 100×40byte | 本編プレイアブル6人分のレベル別ステータス成長表（レコードindex=レベル、0=ダミー、1〜99） |
| `dq7_character_init_data.dat` | 7932byte | nrec=46, rsize=172 | 46×172byte | 全キャラ（本編6人・ゲスト・特殊NPC含む）の初期化データ |
| `dq7_chara_list.dat` | 77888byte | nrec=927, rsize=84 | 927×84byte | 全キャラ・NPCの3Dモデル関連数値一覧（ステータスは含まない） |
| `dq7_player_job.dat` | 10360byte | nrec=55, rsize=188 | 55×188byte | 職業55種の定義 |
| `dq7_job_level.dat` | 84byte | nrec=8, rsize=8 | 8×8byte | 職業熟練度8段階の閾値 |

## `dq7_player_levelN.dat` レコード構造（40byte）

```
+0x00  u16  タグ（用途未確定）
+0x02  u16  0xFFFF マーカー（レコード0は全ゼロ）
+0x04  u32  そのレベルに到達する累計EXP
+0x08  u16  STR相当ステータス
+0x0a  u16  AGI相当ステータス
+0x0c  u16  LUCK相当ステータス
+0x0e  u16  WIS相当ステータス
+0x10  u16  最大HP
+0x12  u16  最大MP
+0x14〜0x27  未使用（0パディング）
```

- 守備力に相当する値は格納されていない（本タイトルでは別の計算式で導出される仕様のため）。
- ファイル番号(1〜6)とキャラID(1〜6)の対応は、別ファイル`dq7_character_init_data.dat`の
  `+0x32`〜`+0x3c`フィールドとのレコード単位の直接バイト比較により**確定済み**
  （下記参照）。

## `dq7_character_init_data.dat` レコード構造（172byte、46レコード、index=キャラID空間）

```
+0x00  u16 0x0000 + u16 0xFFFF マーカー
+0x04  u32  初期EXP
+0x08/+0x0c/+0x10  float×3  初期位置 X/Y/Z（推定）
+0x14/+0x18        float×2  用途不明（疎らに非ゼロ）
+0x1c/+0x20/+0x24  float×3  向き/スケール（推定）
+0x28/+0x2c        float×2  用途不明
+0x30  u16 self_index（レコード自身のindexと常に一致）
+0x32  u16  STR相当ステータス
+0x34  u16  AGI相当ステータス
+0x36  u16  LUCK相当ステータス
+0x38  u16  WIS相当ステータス
+0x3c  u16  HP
       u16  unk4（ほぼ常に0）
+0x40〜0x48  用途不明（ほぼ全ゼロ）
+0x4c  u32  性別（271=男性、272=女性、273=その他・非人間）
+0x50〜0x68  ほぼ全ゼロ
+0x6c  u32  レコード生成順らしき連番（情報用途のみと推定）
+0x70  u32  用途不明
+0x74  u32  初期レベル
+0x78..  ASCII "pNNNN"/"bNNNN" モデル名文字列（直前1byteがモデル番号の10進値）
+0x90  u32（上位u16のみ使用）  キャラ種別を示すコード（厳密な意味・伝達経路は未確定）
+0x94〜0xa8  未使用（全ゼロ）
```

- `+0x32`/`+0x34`/`+0x36`/`+0x38`/`+0x3c`（STR/AGI/LUCK/WIS/HP）は、本編プレイアブル
  4キャラについて`dq7_player_levelN.dat`のレベル1レコードの同項目と**全フィールド
  完全一致**することを実データ比較で確認済み。すなわちこのテーブルの該当フィールドは
  「そのキャラのレベル1時点のステータス」と同一の値を保持している。
- `+0x90`のフィールドは観測範囲で以下の値を取る（意味・下流への伝達経路は未確定）:
  `0x08`（単独の1レコードのみ）/ `0x10`（4レコード）/ `0x310`（1レコード、追加ビット付き）/
  `0x1c`（配置座標等の実データを伴う一群）/ `0x20`（位置・向き等が全ゼロの一群）/
  `0x28`（別の一群、HPフィールドが個別の値を持つ）。
- `+0x74`（初期レベル）・`+0x04`（初期EXP）は、ゲームが新規セーブを作成する際に
  本編プレイアブル枠（キャラID1〜6）のCharactorsスロットへ、まだパーティに未加入の
  キャラ分も含めて一括でコピーされる値であることを、新規セーブの実データとの
  バイト一致で確認済み。
- `+0x90`フィールドの値が「位置・向き等の実データを伴う」一群に属するレコードは、
  STR/AGI/LUCK/HPに個別の固定値を持つ。WISに相当するフィールドはこれらのレコードで
  一律0。HPは、この一群の大半のレコードで共通して同一の高い固定値（999）を持つ一方、
  別の一群（座標等が未設定のプレースホルダ扱い）ではHPを含む全フィールドが0。
  さらに別の一群（特殊キャラ群）はHPが個別に作り込まれた値（300〜3000相当の範囲）を持つ。

## `dq7_chara_list.dat` レコード構造（84byte、927レコード）

全キャラ・全NPCの一覧で、パーティ専用ではない。横断比較の結果、ステータス的な
フィールドは含まれず、3Dモデル関連の数値（バウンディングボックス寸法・スケールと
推定されるfloat値群）が中心であることを確認済み。

```
+0x00  u16 asset_tag（レコードごとにほぼ連番） + u16 0xFFFF マーカー
+0x08..0x44  float×16  3Dモデル関連の寸法/スケール値（厳密な割り当ては未確定）
+0x4c..  ASCII "pNNNN"/"bNNNN" モデル名（固定オフセットではなく、領域内の"p0"文字列を
       検索して抽出する方式が安全——レコードごとに先頭パディング長が異なるため）
```

## ステータス生成の関数経路（ExeFS、ARM、file offsetはベースゲーム基準）

- `PlayerDataContainer::initialize`（`0x12ce18`）がキャラID1〜45全員について
  `PlayerData::setup(this=slot, arg2=id, jobId=id)` を呼ぶ。
- `PlayerDataContainer::deserialize`（`0x23e43c`）がキャラID1〜6のみ、セーブの
  Charactorsブロックの値で`setup()`後の状態を上書きする。
- `PlayerData::setup`（`0x223ab4`）は、渡されたIDが1〜6かどうかで追加初期化の有無を
  分岐しつつ、`dq7_character_init_data.dat`該当レコードのフィールドを`this`へコピーし、
  さらに別テーブル（職業ID参照、記述子`0x3ef540`/`0x679994`）のHP/MP倍率フィールド
  （`+0x3d`/`+0x3e`）を使って `最終値 = floor(ベース値 × 倍率 ÷ 10)` の計算で
  `HaveStatus::setHpMax`（`0x123bf0`）/ `setMpMax`（`0x123b98`）へ値を渡す。

## Webビューアでの対応API

- `parse_player_stats()` / `/api/player_stats`
- `parse_character_init_data()` / `/api/character_init_data`
- `parse_chara_list()` / `/api/chara_list`

## 未確定・未解明の点

- `dq7_player_levelN.dat`の`+0x00`タグフィールドの意味。
- `dq7_character_init_data.dat`の`+0x90`フィールドが「操作可能/AI」判定へ
  どのように伝達されるかの完全な経路。
- `dq7_chara_list.dat`のfloat×16の正確な個別割り当て（min/max/scale等への厳密対応）。
- `dq7_player_job.dat`（188byte×55）の職業補正フィールドの詳細。
- `PlayerData::setup`の`arg2`引数の意味、および`+0x24`/`+0x2a`（HP/MPベース値の
  最終格納先フィールド）への書き込みが行われる正確なコード位置。
