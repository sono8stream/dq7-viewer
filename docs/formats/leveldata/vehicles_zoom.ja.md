# `LEVELDATA/dq7_vehicles.dat`とルーラのメニュー

`dq7_vehicles.dat`はExcelBinaryDataの表（20バイトのヘッダ: マジック、レコード数、レコード長、レコード数、0。
レコードは`+0x14`から）。0x3cバイトのレコードが29個。レコード`d`がルーラの行き先`d`で、そこへルーラしたときに
船と魔法のじゅうたんをどこへ移すかも持つ。

| オフセット | 型 | 意味 |
|---|---|---|
| +0x00 | s32 | 船の場所番号（30000＋その地図の海の出口番号） |
| +0x04 | s32 | どのレコードでも+0x00と同じ |
| +0x08 | s32 | じゅうたんの場所番号（50000＋n） |
| +0x0c | s32 | 船のフロアID |
| +0x10 | s32 | じゅうたんのフロアID |
| +0x14 | f32 ×3 | 船の位置 |
| +0x20 | f32 ×3 | じゅうたんの位置 |
| +0x2c | u16 | 行き先のフロアID |
| +0x2e | u16 | 行き先の出口番号（マップリンク）。その出口から来たのと同じように着く |
| +0x30 | u16 | （ルーラの処理では読まない） |
| +0x32 | u16 | 切り替え先のフロアID |
| +0x34 | u16 | 切り替え先の出口番号 |
| +0x36 / +0x38 | u16 | 切り替えを決めるフラグ（種類0）。+0x3bの極性ビットと組み合わせる |
| +0x3a | u8 | ? |
| +0x3b | u8 | bit 0 / bit 1: +0x36 / +0x38のフラグの極性 |

## ゲームの読み方

- `TownRuraMenu::onOpen`（ベース版0x1c4438）は、種類0の物語フラグ`d`が立っている行き先`d`（1〜25）を、その順に並べる
  （`GameFlag::check(flags, 0, d)`）。
- `TownRuraMenu::onDraw`は名前をメニュー文字`0xe4070 + d`として描く。これは`MENULIST/place_menu.txt`の`#d`。
- `TownRuraMenu::onResult`（0x246e2c）は選んだ`d`を記録する（24は27、25は28に置き換える）。
- `FlowRuraAction::onEnd`／`FlowShipRura::onEnd`は、`LevelDataUtility::getVehiclesFloorId(d)`／`getVehiclesSurfaceId(d)`
  へマップリンクする。値は+0x2c／+0x2e。ただし、+0x38が0でなく、そのフラグが+0x3bのbit 1と一致し、かつ
  （+0x36が0か、そのフラグがbit 0と一致しない）ときは+0x32／+0x34。そのあと船とじゅうたんの欄を乗り物の管理へ写す
  （`DQVehicleManager::setRura`と同じ処理）。
- 行き先のフラグが1つも立っていないと一覧は空になる。`onOpen`は欄を0で埋めるので、決定すると0番目の欄＝行き先0が
  選ばれ、レコード0はすべて0（フロア0）になる。行き先が無い状態でルーラを使うとフリーズした。この経路はコードから
  読んだもので、実行中に追ってはいない。
